# AGENT INSTRUCTIONS — Alchemy Knowledge System

These instructions apply to ChatGPT, Codex, and other agents working with Andrey Li's alchemy materials.

## 1. First-read protocol

Before answering, editing, creating a report, or building a landing:

1. Read `KNOWLEDGE-HUB.md`.
2. Read `method-source-registry.json`.
3. Follow the task route in `KNOWLEDGE-HUB.md`.
4. Read the canonical files listed for that task.
5. Use search only after canonical routing.

Do not begin with broad repository search when the hub or registry already names the source.

## 2. Canonical-source discipline

Distinguish four statuses:

- **canonical** — current source of truth
- **supporting** — examples, explanations, or implementation aids
- **historical** — older wording or superseded model
- **experimental** — unverified drafts, prototypes, or hypotheses

Never present supporting, historical, or experimental content as canonical without an owner decision.

## 3. Preserve the owner's method

Do not replace the owner's terminology with generic psychology, medicine, coaching, or spirituality.

Preserve these core concepts when supported by sources:

- Dao Resource Ladder
- Wu Xing resource balance
- stress subpersonality / hidden mechanism
- dynamic remedy relevance
- step-based development
- one-cycle movement and stabilization
- constellation / field analysis
- psycho-homeopathy / Alchemy of the Soul
- Daoist Alchemy

You may simplify language for clients, but do not change the internal logic.

## 4. Core reasoning chain

Use this chain as the default internal model:

`request → current state → hidden mechanism / stress subpersonality → Dao level → Wu Xing resource → correction → remedy/support resonance → practical action → tracking → next level`

Not every case needs every layer. Include only layers supported by the actual material and relevant to the request.

## 5. Three product routes

### Daoist Alchemy
Use when the primary problem is resource, health, vitality, recovery, stability, or Wu Xing balance.

### Psycho-homeopathy / Alchemy of the Soul
Use when the primary problem is a stress subpersonality, emotional pattern, repeated scenario, fear, inhibition, or goal blockage.

### Business Support
Use when the primary problem is a business bottleneck, risk, opportunity, decision, process, sales, manifestation, or movement of a project.

When unclear, start with a brief diagnosis rather than forcing a route.

## 6. Monthly-program logic

Default offer:

- 2 sessions
- 4 weeks of support
- initial diagnosis
- individual support plan
- tracking and relevance review
- second diagnosis / integration session

Do not promise that every client will move exactly one level. Present one level per cycle as a working model that requires personal verification.

## 7. Dynamic support rule

Never assume a remedy, essence, oil, practice, artifact, or mandala remains relevant throughout the whole cycle.

Track:

- response
- duration of effect
- change in state
- new bottleneck
- capacity to hold the support
- need to adjust or stop

Core rule:

`state changes → support relevance may change`

## 8. Client-facing communication

Use depth inside and simplicity outside.

Preferred structure:

1. What the client is experiencing
2. What the work helps clarify
3. How the process works
4. What the format includes
5. What the next small step is

Avoid leading with a long list of methods.

Do not use medical guarantees or state that the method replaces medical or psychiatric care.

## 9. Evidence and uncertainty

For owner-created symbolic or energetic models, label them as the owner's method, working model, diagnostic framework, or practice-based observation.

Do not present field diagnosis, remote influence, remedy resonance, mandalas, artifacts, or Dao-level measurements as established scientific facts.

When medical or psychological claims are involved:

- distinguish source language from externally verified knowledge
- avoid cure claims
- recommend appropriate professional care for serious or urgent symptoms

## 10. Conflict handling

When two sources conflict:

1. Identify both sources.
2. State the exact conflict.
3. Apply source priority from `KNOWLEDGE-HUB.md`.
4. If the conflict affects the model, pricing, safety, or public promise, request owner resolution.
5. Record the decision in a canonical file and registry.

Known example:
- "each stage has 7 levels" conflicts with the current 18-level structure of 7 health + 7 success + 4 spirit. Use 18 total levels unless the owner changes it.

## 11. Repository boundaries

- Method truth belongs in `alchemy-method`.
- Long-form manuscript and assets belong in `books`.
- Website code belongs in the relevant site repository.
- Business packaging belongs in `ai-projects-brain` or canonical product files.
- Reports may be generated by `dao-usin-bach-report-kit`, but report logic must trace back to `alchemy-method`.

Do not create duplicate canonical definitions across repositories.

## 12. Change protocol

For any structural change:

1. Update or add the canonical method/product file.
2. Update `method-source-registry.json`.
3. Update `KNOWLEDGE-HUB.md`.
4. Add a short migration note when old files remain.
5. Avoid deleting source history unless clearly duplicated and safely archived.

## 13. Minimum quality check

Before finalizing an output, verify:

- Is the source route correct?
- Is the terminology consistent?
- Is the product route clear?
- Is the current state distinguished from the desired state?
- Is the next step concrete?
- Are uncertain claims labeled?
- Are safety boundaries respected?
- Is the output concise enough for its audience?
